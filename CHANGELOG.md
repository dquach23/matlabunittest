# Changelog

All notable changes to matlabunittest are recorded here.  From v1.3
onward, cycles are named after the bumped DocVersion they ship in
the autogenerated test reports; PHASE<N>_HANDOFF.md files are kept
for the pre-1.3 history but new cycles use V1_<N>_HANDOFF.md.

The autogen is **scaffolding plus invariants**, not "tests that know
your spec."  Each cycle tries to flip more autogenerated tests from
Failed/Incomplete to Pass without introducing per-project knowledge
into the +autotest package.

### Added (autogen mechanisms)
- `+autotest/InputSampler.m::hasValidator(validatorsBraces, name)`:
  word-boundary regex check for a single-constraint validator inside
  an arguments-block validators slot.  Used by typesFromArguments to
  detect `mustBeNonempty`, `mustBeFinite`, `mustBeReal`, `mustBePositive`,
  `mustBeText`, `mustBeTextScalar`, `mustBeNonzeroLengthText`.  Generic
  across MATLAB projects.  v1.3 candidate 2.
- `+autotest/InputSampler.m::filterEdgesByValidators(edges, t)`:
  drops edges that the declared validators reject upfront
  (empty/nan/inf for MustBeNonempty/MustBeFinite, zero/neg for
  MustBePositive).  Keeps the edge ladder honest -- only edges the
  function actually has a chance of processing remain.  v1.3 candidate 2.
- `+autotest/InputSampler.m::typesFromArguments`: extended to
  capture the new constraint flags into per-arg info (MustBeNonempty
  / MustBeFinite / MustBeReal / MustBePositive / MustBeText).  When
  MustBeText is set on a row that didn't otherwise pin a Type, the
  Type is surfaced as `string` so randomArgsExpr and scalarFor pick
  the string ladder.
- `+autotest/InputSampler.m::typesFromArguments`: composite stringy-
  suffix parity with FixtureProvider.  In addition to the exact-
  match list, identifiers ending in `titletext`, `headertext`,
  `subtitle`, `text`, `message`, `name`, `string`, `label`, `caption`
  (length >= 5) are retyped to string.  Stops the randomized layer
  from feeding rand() into a downstream `strlength` / `regexp` chain
  on names that didn't make the original exact-match list.  Generic
  across MATLAB projects; pure name match.
- `+autotest/TestWriter.m::randomArgsExpr`: scalar-shaped name
  detection.  Args whose names contain `col` / `row` / `index` /
  `sheetnumber` (or are exactly `startCol` / `endCol` / `startRow` /
  `endRow`) and have no explicit type get `randi(10)` (positive
  scalar) instead of `rand(1, randi(5))` (vector).  Stops the
  randomized layer from feeding a vector into a colon endpoint or
  array index.  Also respects `MustBePositive`: when the validator
  is set, switches numeric randomization to `randi(10, 1, randi(5))`
  so 0 and negatives never appear.

### Added (native MATLAB report generator)
- `+autotest/+report/ReportBuilder.m::embedSelfChecksum(docxPath)`:
  v1.3 Part B item 2 -- two-pass self-attestation.  After
  backend.close() writes the .docx, unzips into a temp stage,
  computes sha256 of `word/document.xml` AS WRITTEN (with the
  `__DOCX_SHA256_SLOT__` sentinel still in place), substitutes the
  sentinel for the hash, re-zips.  The inline hex is the pre-
  substitution content hash; reviewers verify by reverse-substituting
  the hex back to the sentinel inside `word/document.xml` and
  rehashing -- the result matches the inline hex.  Hash is over
  document content (not the zip wrapper) so verification is robust
  to MATLAB's non-deterministic zip metadata.  Best-effort:
  failures are non-fatal (sentinel just stays in place; sidecar
  still carries the post-write file hash).
- `+autotest/+report/ReportBuilder.m::tryRmdir/listStageFiles`:
  helpers for embedSelfChecksum.
- `+autotest/+report/SectionBuilder.m::appendixE`: new subsection
  E.5 "Self-attesting Content Checksum".  Carries the sentinel
  marker, the verification recipe, and the cross-reference to the
  audit sidecar.  Replaced the obsolete "sha256 cannot be embedded
  in itself" caveat with the actual two-pass approach.

## Phase 15 -- 2026-05-07

### Added (autogen mechanisms)
- `+autotest/InputSampler.m::firstKeyOr(container, fallback)`: returns
  the first key/index of a populated `containers.Map` / `dictionary` /
  `struct` / `cell` / `table`, or the `fallback` literal verbatim when
  empty / unrecognised.  Backs the Phase 15 candidate 1 (live-state-
  aware smoke) substitution.  All-or-nothing safety: any throw / shape
  miss returns fallback.  Generic across MATLAB projects.
- `+autotest/StateInitializer.m::liveKeyExpr(propName, propType, fallback)`:
  emits `autotest.InputSampler.firstKeyOr(testCase.Instance.<propName>,
  <fallback>)` for use as a smoke arg expression.
- `+autotest/TestWriter.m::applyLiveKeySubstitution(smartCase, fcn, kind)`:
  walks smart-case Args; for each input whose name is key-shaped (suffix
  `name`/`id`/`key`) AND partial-matches a class container property
  by `startsWith(lprop, base)` + `endsWith(lprop, container_suffix)`
  (or direct equality), replaces the synthetic literal with the
  live-key expression.  Sets `DropStatefulWrap = true` so
  `appendCallTest` drops the Phase 11 try/assumeFail wrap on the
  substituted smoke.
- `+autotest/TestWriter.m::matchArgToProperty(argName, props)`: helper
  for the partial-match algorithm.  Public properties only.
- `+autotest/TestWriter.m::tryDomFullFixtureSmoke(fcn, provider)`:
  Phase 15 candidate 4.  Pre-pass: if at least one arg is DOM-typed/
  named AND every non-DOM arg resolves via FixtureProvider, build a
  smoke that uses tempDOM for DOM args and fixture literals for the
  rest.  Half-fixture smokes are aborted (Phase 12 lesson).
- `+autotest/FixtureProvider.m`: typed `data` / `value` / `payload`
  fixture branch.  When an `arguments` block declares one of these
  names with an explicit type AND a recognised SizeHint, return a
  type+shape-appropriate fixture (string, char, double scalar/vector/
  matrix, logical, table, cell, struct).  Gated on
  `argInfo.IsExplicit`.  Phase 15 candidate 5.
- `+autotest/TestWriter.m::appendCallTest`: now honours
  `sample.DropStatefulWrap` (skip wrapStateful) and `sample.AnnotateArgs`
  (emit `% Phase 15 cand-4 Args = {...}` leading comment for post-mortem).
