# Changelog

All notable changes to matlabunittest are recorded here.  Phase numbers
match the corresponding `PHASE<N>_HANDOFF.md` files.

The autogen is **scaffolding plus invariants**, not "tests that know
your spec."  Each phase tries to flip more autogenerated tests from
Failed/Incomplete to Pass without introducing per-project knowledge
into the +autotest package.

## Phase 16 -- 2026-05-07

### Added (autogen mechanisms)
- `+autotest/InputSampler.m::firstValueOr(container, fallback)`:
  returns the first VALUE entry of a populated `containers.Map` /
  `dictionary` / `struct` / `cell` / `table`, or the FALLBACK literal
  verbatim when empty / unrecognised.  Symmetric to Phase 15's
  `firstKeyOr`.  Backs Phase 16 candidate 2 (live-state-aware VALUE
  synthesis).  Generic across MATLAB projects.
- `+autotest/InputSampler.m::typesFromArguments`: extended to capture
  `info.MustBeMember` (cell array of allowed values) when an
  `arguments` block declares `mustBeMember(arg, list)` with a
  literal list.  Generic across MATLAB projects.  Phase 16 candidate 4.
- `+autotest/InputSampler.m::parseMustBeMember/parseAllowedListLiteral/scanQuoted`:
  paren-balanced parser for the validators slot.  Recognises string
  array (`["a","b"]`), cellstr (`{'a','b'}`), and numeric array
  (`[1 2 3]`) list forms; symbol references return empty so the
  consumer cleanly falls back.
- `+autotest/StateInitializer.m::liveContainerExpr(propName, propType)`:
  emits `testCase.Instance.<propName>` so the smoke uses the entire
  container property at runtime.  Phase 16 candidate 1.
- `+autotest/StateInitializer.m::liveValueExpr(propName, propType, fallback)`:
  emits `autotest.InputSampler.firstValueOr(testCase.Instance.<propName>,
  <fallback>)` for value-shaped args.  Phase 16 candidate 2.
- `+autotest/TestWriter.m::applyContainerSubstitution(smartCase, fcn, kind)`:
  walks smart-case Args; for each position whose declared/inferred
  type matches a class container property (containers.Map /
  dictionary / table / struct) AND whose name matches by shape +
  similarity, replaces the synthetic literal with
  `testCase.Instance.<propName>`.  Sets `DropStatefulWrap = true`
  when any substitution happened.  Phase 16 candidate 1.
- `+autotest/TestWriter.m::matchArgToContainerProperty(argName, argType, props)`:
  helper for candidate 1.  Skips key-shaped args (handled by the
  Phase 15 key path), matches by shape OR plural-aware name suffix.
- `+autotest/TestWriter.m::matchArgToValueProperty(argName, argType, props)`:
  helper for candidate 2.  Returns property name + type when the
  arg is value-shaped (table / struct / cell) AND a public class
  property of the same value type matches by name.
- `+autotest/TestWriter.m::applyLiveKeySubstitution`: extended to
  fall through to the value path when no key match is found.
  Phase 16 candidate 2 builds on top of Phase 15 candidate 1's
  framework.
- `+autotest/TestWriter.m::markDropStatefulWrapIfClean(smartCase, fcn, kind)`:
  Phase 16 candidate 3 wrap-drop gate.  Sets `DropStatefulWrap = true`
  when (a) every smart-case arg resolved cleanly via FixtureProvider /
  live-key / live-container, (b) the model has at least one state-init
  candidate detected by `StateInitializer.candidateMethodCalls`,
  (c) the FixtureProvider has at least one primary fixture
  (PrimaryExcel / PrimaryImage / PrimaryKeepList).
- `+autotest/TestWriter.m::fixtureProviderHasPrimary(provider)`:
  helper for candidate 3.  Boolean guard for (c).
- `+autotest/FixtureProvider.m`: new mustBeMember branch.  Inserted
  AFTER the Phase 14 typed table/cell branch and BEFORE the Phase 15
  cand-5 data/value/payload branch; consumes `argInfo.MustBeMember`
  to emit a literal that's guaranteed to satisfy validation on the
  first call.  Phase 16 candidate 4.
- `+autotest/MFileParser.m::collectExampleBlock`: rewritten to
  tolerate multi-line bodies with internal blank lines.  Termination
  conditions: recognised heading (`See also:`, `Inputs:`, `Outputs:`,
  `Notes:`, etc.), two consecutive blank lines, or single blank
  followed by an unindented non-heading.  Indented (2+ spaces) lines
  remain continuation regardless of intervening single blanks.
  Phase 16 candidate 5.
- `+autotest/MFileParser.m::isHelpSectionHeading(trimmed)`: helper
  for candidate 5; recognises the conventional MATLAB help-text
  section headings that terminate an Example: body.
- `+autotest/TestWriter.m::appendDocExampleTest`: when the extracted
  example contains an `=` assignment, route through
  `runIsolatedExample` so the eval runs in a clean local frame
  (clearvars first).  Plain non-assignment examples keep the
  original `runExample` path.  Inlined `runIsolatedExample(~, text)`
  helper added to the generated test class so generated tests stay
  self-contained (no runtime dependency on +autotest).

### Added (native MATLAB report generator)
- `+autotest/+report/+backends/OoxmlBackend.m`: page-number footer

  of `<w:body>` carries the footer reference.  Two-section sectPr
  proper (cover + main).  Phase 16 Part B item 2.
- `+autotest/+report/+backends/RptgenBackend.m`: centred Page X of Y
  footer attached to the first `PageFooters` slot in the constructor.
  Mirrors OoxmlBackend so visible output is consistent across
  backends.  Best-effort: rptgen footer API varies between
  R-versions; failure is non-fatal.  Phase 16 Part B item 1.
- `+autotest/+report/+backends/RptgenBackend.m::close`: best-effort
  `rmdir(_docs, 's')` to remove the per-document `_docs` intermediate
  that mlreportgen.dom emits next to the .docx.  Phase 16 Part B
  item 4.
- `+autotest/+report/PdfBackend_LibreOffice.m`: NEW class wrapping
  the LibreOffice PDF tier with a UNO Basic macro that walks
  `oDoc.DocumentIndexes` and updates each one before
  `storeToURL writer_pdf_Export`.  Provisions a fresh
  `-env:UserInstallation=...` profile with the macro library
  pre-installed; falls back to bare `--convert-to pdf` when the
  macro path can't be provisioned.  Phase 16 Part B item 3.
- `+autotest/+report/Style.m::FooterFontSize`: new constant (9pt).
- `+autotest/+report/DefectRegister.m::groupStatefulByCluster(tests)`:
  cluster Incomplete tests by class AND message signature.  Each
  distinct failure cluster within a class gets its own defect ID
  instead of collapsing into one per-class entry.  Phase 16 Part B
  item 5.
- `+autotest/+report/DefectRegister.m::clusterSignature/mostCommonMessage/titleSuffixFromMessage/userStubMitigation`:
  helpers for the cluster-grained refactor.  Findings field cites
  the most common diagnostic verbatim (truncated to 200 chars);
  Status field maps RR-NNN to user-stub file paths.
- `+autotest/+report/DefectRegister.m`: new `AffectedMethods` field
  on every defect entry (cell array of method names).  The stateful
  cluster path populates it; other categories get `{}`.  Used by
  Appendix B's diagnosticSamples to filter samples to the cluster's
  actual methods.
- `+autotest/+report/SectionBuilder.m::diagnosticSamples`: cap raised
  from 3 to 6 samples per defect.  When the defect carries
  `AffectedMethods`, prefers samples from those exact methods
  (cluster-precise filtering).  Belt-and-braces guarantees every
  Section-6 DEFECTID gets at least one sample in Appendix B.
  Phase 16 Part B item 6.
- `+autotest/+report/SectionBuilder.m::appendixE`: NEW.  Audit Trail
  appendix listing matlabunittest commit hash, tree-clean status,
  test-cycle timestamp, Phase 16 verification status, Pass / Fail /
  Incomplete counts, chosen backend, PDF tier, and a reference to
  the audit sidecar published next to the deliverables.  Phase 16
  Part B item 7.
- `+autotest/+report/SectionBuilder.m::appendixC`: extended to call
  out the Phase 16 candidates (1-5) alongside the Phase 15 ones in
  the methodology note.  Section numbering renumbered: C.3 is now
  Phase 16 Additions, C.4 known_real_signal.txt Opt-Out, C.5 Native
  Report Generator.
- `+autotest/+report/ReportBuilder.m::collectAudit/gitProvenance/writeAuditSidecar/sha256OfFile`:
  audit data collection + sidecar writer.  Captures provenance via
  `system('git rev-parse HEAD')` and `git status --porcelain` from
  the matlabunittest repo path (resolved from `mfilename('fullpath')`,
  no `pwd` dependency).  Computes sha256 of the .docx and .pdf
  AFTER both deliverables are written; emits the
  `<basename>_TestReport_audit.txt` sidecar carrying the hashes.
- `+autotest/+report/ReportBuilder.m`: integrated `PdfBackend_LibreOffice`
  into the libreoffice tier (replaces the inline implementation).

## Phase 15 -- 2026-05-07

### Added (autogen mechanisms)
- `+autotest/InputSampler.m::firstKeyOr(container, fallback)`: returns
  the first key/index of a populated `containers.Map` / `dictionary` /
  `struct` / `cell` / `table`, or the `fallback` literal verbatim when
  empty / unrecognised.  Backs the Phase 15 candidate 1 (live-state-
  aware smoke) substitution.  All-or-nothing safety: any throw / shape
  miss returns fallback.  Generic across MATLAB projects.
- `+autotest/StateInitializer.m::liveKeyExpr(propName, propType, fallback)`:
  emits `autotest.InputSampler.firstKeyOr(testCase.Instance.<propName>,
  <fallback>)` for use as a smoke arg expression.
- `+autotest/TestWriter.m::applyLiveKeySubstitution(smartCase, fcn, kind)`:
  walks smart-case Args; for each input whose name is key-shaped (suffix
  `name`/`id`/`key`) AND partial-matches a class container property
  by `startsWith(lprop, base)` + `endsWith(lprop, container_suffix)`
  (or direct equality), replaces the synthetic literal with the
  live-key expression.  Sets `DropStatefulWrap = true` so
  `appendCallTest` drops the Phase 11 try/assumeFail wrap on the
  substituted smoke.
- `+autotest/TestWriter.m::matchArgToProperty(argName, props)`: helper
  for the partial-match algorithm.  Public properties only.
- `+autotest/TestWriter.m::tryDomFullFixtureSmoke(fcn, provider)`:
  Phase 15 candidate 4.  Pre-pass: if at least one arg is DOM-typed/
  named AND every non-DOM arg resolves via FixtureProvider, build a
  smoke that uses tempDOM for DOM args and fixture literals for the
  rest.  Half-fixture smokes are aborted (Phase 12 lesson).
- `+autotest/FixtureProvider.m`: typed `data` / `value` / `payload`
  fixture branch.  When an `arguments` block declares one of these
  names with an explicit type AND a recognised SizeHint, return a
  type+shape-appropriate fixture (string, char, double scalar/vector/
  matrix, logical, table, cell, struct).  Gated on
  `argInfo.IsExplicit`.  Phase 15 candidate 5.
- `+autotest/TestWriter.m::appendCallTest`: now honours
  `sample.DropStatefulWrap` (skip wrapStateful) and `sample.AnnotateArgs`
  (emit `% Phase 15 cand-4 Args = {...}` leading comment for post-mortem).

### Added (native MATLAB report generator)
- `+autotest/generateSystemTestReport.m`: public API that produces
  `<OutputDir>/<basename>_TestReport.docx` (and a matching `.pdf`)
  using only MATLAB primitives.  Selects between two backends and
  logs the choice to `<OutputDir>/report_backend.log`.
- `+autotest/+report/ReportBuilder.m`: top-level orchestrator.
  Resolves options, probes the backend, parses results, builds the
  defect register, emits the report, drives the PDF tier.
- `+autotest/+report/ResultsParser.m`: reads `summary.txt` /
  `results.xml` / `known_real_signal.txt` into a single struct.
- `+autotest/+report/SourceInventory.m`: walks PROJECT_PATH for
  `.m` and `.mlapp`, pulls H1 / classdef summary verbatim.  Falls back
  to a one-line factual description marked as derived when no help
  text is present.
- `+autotest/+report/DefectRegister.m`: categorises Incompletes into
  defect entries with PROJECT_PREFIX-NNN IDs.  Differentiates real
  project bugs (from known_real_signal.txt), autogen-side limitations
  (opaque-typed input, stateful-input mismatch), and by-design
  user-stub placeholders.  Severity ratings defended in prose.
- `+autotest/+report/SectionBuilder.m`: emits Sections 1..9 + Appendices
  A..D via the backend's heading / paragraph / table API.  Methodology
  note (Appendix C) cites Phase 15 candidates 1 / 4 / 5.
- `+autotest/+report/CoverPage.m`: title block + metadata table +
  bordered Distribution Statement D.
- `+autotest/+report/BackendDetector.m`: probes available backends
  (RptgenBackend then OoxmlBackend) and PDF tiers.  Errors fail-loud
  if neither tier is available.
- `+autotest/+report/Style.m`: shared font / size / colour / spacing
  constants.
- `+autotest/+report/+backends/RptgenBackend.m`: primary path using
  `mlreportgen.dom.Document` + `mlreportgen.utils.docToPDF`.
- `+autotest/+report/+backends/OoxmlBackend.m`: hand-rolled OOXML
  fallback.  Composes `[Content_Types].xml`, `_rels/.rels`,
  `word/document.xml`, `word/styles.xml`, `word/settings.xml` etc. as
  char vectors and packs with builtin `zip()`.  TOC field with
  `<w:updateFields w:val="true"/>` so Word refreshes page numbers on
  first open.
- `_phase15_run_all.m`: end-to-end MATLAB driver for verification.
- `_phase15_ver.m`: ad-hoc `ver` capture (superseded by run_all).
- `PHASE16_HANDOFF.md`: the next-phase brief.

## Phase 14 -- 2026-05-06

### Added
- `+autotest/InputSampler.m::tempUnzippedExcel(testCase, sourceXlsx)`:
  unzips the given workbook into a temp directory, registers a
  recursive cleanup teardown, returns the dirPath.  Falls back to a
  bare `tempname()` when the source file is missing or unreadable.
- `+autotest/InputSampler.m::cleanupTempDir(dirPath)`: best-effort
  recursive removal of the unzipped staging directory.
- `+autotest/FixtureProvider.m`: typed table / cell fixture branch.
  When an `arguments` block declares an arg as `table` or `cell`,
  return a small synthetic `table([1;2;3], ["a";"b";"c"], ...)` or
  `{1, 'a'; 2, 'b'}` respectively.  Gated on `argInfo.IsExplicit`
  so the heuristic is dormant when no `arguments` block is present.
- `+autotest/FixtureProvider.m`: unzipped-Excel staging fixture.
  When an arg looks like an unzip / staging directory AND the
  project's primary `.xlsx` is non-empty, return an expression that
  unzips the workbook into a temp dir at TestMethodSetup time.
  Generic across any project that pairs an Excel fixture with a
  class taking a path-like staging arg.
- `PHASE15_HANDOFF.md`.

### Changed
- No call-site changes in `TestWriter.m`.  Phase 14 wires through
  the existing `smartFor` -> `FixtureProvider.literalForArg`
  pipeline used by every constructor and method smoke.

### Results
- removal_redaction_tool: 934/0/42 (Pass / Failed / Incomplete);
  unchanged from Phase 13 in counts, but the regenerated
  `tExcelProcessor.m` now constructs the instance with a real
  unzipped `toolTester.xlsx` directory and `loadAllDOMs()` /
  `buildLookupMaps()` populate `DomCache` / `SheetMap` /
  `RIdToTarget` for real.  Pass count flat because Phase 11's
  stateful-smoke `try / assumeFail` wrap still catches synthetic-
  input mismatches and reports them as Incomplete rather than
  Failed.
- matlabunittest/examples: 95/0/0; both Phase 14 heuristics dormant
  (no `.xlsx` files; no `arguments` blocks declaring `table` or
  `cell`).
